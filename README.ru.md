# dsh-image-studio

Вкладка **«Изображения»** для [DeepSeek Harness](https://github.com/deepseek-ai/deepseek-harness): одна страница, где
можно генерировать картинки через [fal.ai](https://fal.ai), хранить всё в общей студии или прямо в проекте, листать
всё, что вы когда-либо нагенерировали, выбирать лучший кадр, импортировать картинку по ссылке и тут же отдавать
победителя в Kling как image-to-video.

[English version →](README.md)

```text
Изображения
┌────────────────────────────────────────────────────────────────────────────┐
│ Опишите изображение…                                                       │
│  Модель: FLUX.2 Klein 9B ▾  [＋ Своя модель]   Формат: 1:1 ▾                │
│  Вариантов: 4 ▾                                       [Сгенерировать]      │
├────────────────────────────────────────────────────────────────────────────┤
│  Галерея | Шаблоны | Монтаж    Все · Картинки · Видео · Избранное           │
│                                [Импорт по ссылке]  [Поиск по промпту]       │
│  ┌────────┐ ┌────────┐ ┌────────┐ ┌────────┐                                │
│  │  🖼     │ │  🖼     │ │  🎬 5s │ │  🖼     │  клик → просмотр              │
│  └────────┘ └────────┘ └────────┘ └────────┘  → «Оживить в Kling»           │
└────────────────────────────────────────────────────────────────────────────┘
```

## Быстрый старт

1. **Установите** плагин (см. [Установка](#установка)) и откройте **«Изображения»** в сайдбаре.
2. **Вставьте ключ fal.ai** в **Настройки → Плагины → Изображения (fal.ai)** и нажмите **«Сохранить»**: подробнее —
   [Откуда берётся ключ fal](#откуда-берётся-ключ-fal).
3. **Опишите изображение**, выберите модель, формат и количество вариантов, нажмите **«Сгенерировать»**.
4. Кликните по результату: в просмотрщике можно скачать оригинал, скопировать промпт, поставить «в избранное» и
   нажать **«Оживить в Kling»**.

## Что внутри

- **Настоящая страница, а не сообщение в чате.** В сайдбаре появляется пункт **«Изображения»**: сверху промпт, выбор
  модели, формата и количества вариантов (от 1 до 8), снизу — галерея.
- **Под капотом fal.ai.** Три семейства text-to-image подключены с теми полями, которые объявлены в OpenAPI самого
  fal: `fal-ai/flux-2/klein/9b` (FLUX.2 Klein 9B — быстро и недорого), `openai/gpt-image-2` (GPT Image 2 — качество
  и текст на картинке), `fal-ai/nano-banana-2` (Nano Banana 2 — Gemini, 0.5K–4K).
- **Любая другая модель fal — без ожидания релиза.** Кнопка **«＋ Своя модель»** рядом с выбором модели сохраняет любой
  slug endpoint'а fal (`owner/name`) в настройках плагина, после чего он появляется в списке как встроенный.
- **Всё, что вы сгенерировали, остаётся на месте.** Результаты ложатся в папку студии на диске, рядом — индекс.
  Поэтому просмотр ничего не стоит, переживает перезапуск и работает, даже когда провайдер недоступен. Есть
  избранное, поиск по промпту и фильтры по типу.
- **Галерея может жить внутри проекта.** По умолчанию это общая студия `<DSH_HOME>/image-studio`, но переключатель
  **«Источник медиа»** в шапке страницы умеет направить ту же страницу в `<проект>/dsh-media` — чтобы кадры и клипы
  лежали рядом с кодом, к которому относятся. Корень вычисляется на каждый запрос, поэтому переключение не требует
  перезапуска.
- **И карточка в правой панели.** Если в харнессе есть реестр вкладок правой панели, плагин добавляет туда пункт
  **«Медиа проекта»**, открывающий ту же страницу, — галерея может оставаться рядом с терминалом.
- **Импорт по ссылке.** Вставьте прямую ссылку `http(s)` на картинку или видео — файл скачается в ту же галерею.
- **Просмотрщик, которым реально пользуешься.** Кадр на весь экран, скачивание оригинала, копирование промпта, отметка
  «в избранное» и кнопка **«Оживить в Kling»** — та самая картинка уходит в Kling.
- **Вкладка «Монтаж».** Соберите клипы и кадры в таймлайн, выберите 9:16 / 4:5 / 1:1 / 16:9 — хост склеит их в один
  h264-файл через ffmpeg: каждый сегмент сначала приводится к одному размеру, частоте и пиксельному формату, затем
  склейка без перекодирования. Кадр превращается в клип цикличным повтором на выбранное время.
- **Шаблоны.** Восемь стартовых промптов (продукт на подиуме, лайфстайл, UGC-селфи, флэтлей, до/после, сезон, лист
  персонажа, фуд-клоуз) на русском и английском. Шаблон только заполняет поле промпта — деньги тратятся лишь после
  нажатия «Сгенерировать».
- **Два языка интерфейса** — русский и английский, по языку интерфейса.
- **Ключ не покидает хранилище.** Карточка настроек пишет ключ fal через credential-seam харнесса: хост никогда не
  возвращает значение на страницу и никогда не сохраняет секрет в конфигурацию.

## Требования

| Требование | Для чего нужно |
|---|---|
| Ядро DSH `0.2.0-rc.2` (проверено также на `0.2.0-rc.1`) | Host-половина и страница. См. [compatibility.json](compatibility.json). |
| Node.js `^22.19.0 \|\| >=24.0.0` | Всё; объявлено в `package.json`, CI гоняет Node 22.x и 24.x. |
| `ffmpeg` в `PATH` либо `ffmpegPath` в настройках строки | Только вкладка **«Монтаж»**. Без него вкладка так и скажет и не предложит действие; генерация, галерея и Kling работают. |
| Аккаунт fal.ai и ключ | Только генерация и Kling. Просмотр, импорт и монтаж ключа не требуют. |
| Windows или macOS | Поддерживаются обе системы. Нативных модулей, шага сборки и вызовов шелла нет; единственный внешний процесс — ffmpeg, и только для монтажа. |

React 18 и клиентские пакеты DSH, на которых построена страница, поставляет сам харнесс (необязательные
peer-зависимости), поэтому установка из git не требует разрешения на build-скрипты.

## Установка

### Через страницу плагинов (рекомендуется)

1. Откройте **Плагины → Добавить плагин**.
2. Вставьте спецификацию репозитория и установите:

   ```text
   github:naletko/dsh-image-studio
   ```

   Локальная копия тоже подойдёт — вставьте абсолютный путь к папке. Голое имя `dsh-image-studio` сработает, когда
   пакет доступен в npm-реестре, которым пользуется профиль.
3. Установите; если плагин попросит перезапуск — перезапустите харнесс. После этого в сайдбаре появится пункт
   **«Изображения»**.

### Из терминала

```sh
dsh plugin --profile web add github:naletko/dsh-image-studio      # веб-профиль
dsh plugin --profile desktop add github:naletko/dsh-image-studio  # только когда DSH Desktop полностью закрыт
dsh --profile web --dump-config                                   # собрать дерево, не запуская его
```

Профиль `desktop` принадлежит приложению DSH Desktop: пока оно запущено, терминальное управление отклоняется — там
используйте **Плагины → Добавить плагин**.

Чтобы убрать плагин, используйте **Плагины → Удалить** или `dsh plugin --profile web remove dsh-image-studio`. Папка
библиотеки (общая студия или `dsh-media` проекта), ключи и остальные плагины при этом не трогаются.

## Откуда берётся ключ fal

Ключ — это **ссылка на credential**, а не значение в конфигурации. Конфигурация (`cordis.patch.yml`, патч профиля,
`config.json`) хранит только *имя* ссылки — по умолчанию `FAL_API_KEY` — и никогда сам ключ.

Возьмите ключ на [fal.ai](https://fal.ai) → **Keys**; это вся строка `key_id:key_secret`.

Проще всего сохранить его так:

1. Откройте **Настройки → Плагины → Изображения (fal.ai)**.
2. Вставьте целиком строку `key_id:key_secret` и нажмите **«Сохранить»**. Плагин запишет её через credential-seam
   харнесса (`ctx.credentials`).
3. Поле работает только на запись: хост отвечает, *задан ли* ключ и *откуда* он взялся, но никогда — каким он был.
   Следующая генерация сразу использует новый ключ, перезапуск не нужен.

Порядок поиска значения — родной для харнесса:

1. окружение запуска (`FAL_API_KEY=… dsh`) — из приложения не перезаписывается;
2. хранилище ключей `~/.dsh/.credentials.yaml`:

   ```yaml
   version: 1
   refs:
     FAL_API_KEY: <key_id>:<key_secret>
   ```

3. `<рабочая папка>/.env`, затем `~/.dsh/.env`.

Если ключ взят из окружения, карточка так и говорит, а сохранение со страницы заблокировано — окружение главнее. Имя
ссылки можно поменять в настройках строки (`falKeyRef`) — удобно, если на машине ключи лежат под другим именем. Ключ
читается из хранилища на каждый вызов, так что его замена не требует перезапуска.

## Как выбрать модель — включая свою

В списке три endpoint'а fal (см. **«Что внутри»**). Для всего остального:

1. Нажмите **«＋ Своя модель»** рядом с выбором модели.
2. Вставьте slug endpoint'а fal — часть `owner/name` из адреса endpoint'а, например `fal-ai/qwen-image`.
3. Нажмите **«Добавить»**. Slug запомнится в настройках плагина (`config.json` в папке студии), появится в списке с
   пометкой `· своя` и сразу станет выбранным. Убрать его можно чипом **✕**; хранится до 40 слагов.

Принимается только корректный slug вида `owner/name`: голое слово, URL или дубликат встроенной модели просто
игнорируются, и одна плохая запись не выбрасывает весь список. Каталога моделей fal плагин не держит: он отправляет
промпт и те поля, которые объявлены для выбранного семейства. Если endpoint'у нужно поле, которого плагин не
отправляет, задача завершится ошибкой самого fal — страница покажет её текст как есть.

## Импорт по ссылке

**«Галерея» → «Импорт по ссылке»** → вставьте прямую ссылку на картинку или видео → **«Скачать»**.

Хост скачивает ссылку на своей стороне и кладёт результат в ту же галерею, что и всё остальное (ссылка остаётся
подписью записи). Принимаются только ссылки, которые плагину позволено открывать: исключительно `http` и `https`, а
loopback, приватные, link-local и хосты `.local`/`.internal` отклоняются — чтобы маршрут нельзя было использовать как
разведку вашей локальной сети. Импортированный файл всё равно должен укладываться в лимит студии (64 МБ на файл).

## Kling: оживление кадра

Откройте кадр в просмотрщике и нажмите **«Оживить в Kling»**:

- **модель видео** — по умолчанию Kling v3 Pro image-to-video, второй вариант — Kling v3 Standard text-to-video (для
  видео-записи предлагается только text-to-video: у неё нет кадра для оживления);
- **промпт движения** — что должно происходить в кадре;
- **длительность** — 3, 5, 8, 10 или 12 секунд (по умолчанию 5).

Выбранный кадр уходит в fal как data URI: ни шага загрузки, ни публичной ссылки не нужно. Задача опрашивается, пока
Kling рендерит (в пределах `videoTimeoutMs`, по умолчанию 15 минут — Kling рендерит минутами), затем клип попадает в
галерею рядом с исходным кадром.

## Монтаж

Вкладка **«Монтаж»** собирает клипы и кадры в таймлайн в том порядке, в котором вы их расставили (Выше / Ниже /
Убрать), затем:

- **формат** — 9:16 (по умолчанию), 4:5, 1:1 или 16:9;
- **секунд на кадр** — сколько держать статичный кадр (по умолчанию 3, максимум 30);
- до 40 сегментов в одном ролике.

Хост приводит каждый сегмент к одному размеру, 30 fps, кодеку и пиксельному формату во временной папке, затем
склеивает их concat-демуксером ffmpeg без перекодирования и кладёт результат в галерею как обычное видео. Это
склейка, а не редактор: переходов, музыки и титров пока нет. Нужен ffmpeg — он ищется в `PATH`, если `ffmpegPath` не
указывает на конкретный файл; если его нет, вкладка так и говорит вместо того, чтобы предлагать действие.

## Обновление

Плагин обновляет себя сам — удалять и ставить заново ничего не нужно:

- **Страница «Плагины» → карточка Image Studio (или «Настроить» у строки) → «Обновления»**: плагин спрашивает у
  GitHub ревизию ветки, показывает установленную версию рядом с версией на `main`, перечисляет свежие коммиты и одной
  кнопкой отдаёт закреплённый коммит менеджеру плагинов харнесса.
- Если ветка ушла вперёд, в шапке страницы, рядом со счётчиками, появляется кнопка **«Обновить → <версия>»**. Когда в
  сборке нет менеджера плагинов, кнопка неактивна, а её подсказка печатает строку для ручной установки.
- После обновления обновите страницу: изменение браузерной половины применяется сразу, а host-половине нужен
  перезапуск приложения — раздел сам об этом скажет, если работающая версия не сменилась.
- Если менеджера плагинов в сборке нет, тот же раздел печатает строку для **«Плагины → Добавить плагин»**:

  ```text
  github:naletko/dsh-image-studio
  ```

Проверка читает ровно две вещи: `raw.githubusercontent.com/<repo>/main/package.json` и GitHub commits API по
собственному репозиторию плагина (`updateRepo`, по умолчанию `naletko/dsh-image-studio`). Результат кэшируется на
пять минут, а `updateCheck: false` в настройках строки полностью выключает эту функцию. Спецификацию установки плагин
собирает сам из настроенного репозитория и проверенного хеша коммита — никогда из запроса, поэтому подделанный вызов
не может попросить менеджер пакетов о чём-то другом.

## Где живёт библиотека

Медиа может лежать в одном из двух мест. Их выбирает переключатель **«Источник медиа»** в шапке страницы — или те же
ключи `library*` в настройках строки:

```text
Источник медиа:  Источник: Общая студия ▾   Подпапка: ▾   [Применить]   Папка: <фактический корень>

librarySource: studio                                  →  <DSH_HOME>/image-studio
librarySource: workspace, libraryWorkspace: /path/to/project, librarySubdir: shots/2026
                                                       →  /path/to/project/dsh-media/shots/2026
```

| Источник | Где лежит медиа | Примечания |
|---|---|---|
| **Общая студия** (по умолчанию) | `<DSH_HOME>/image-studio/` | Одна галерея на машину, не привязана ни к какому проекту. |
| **Проект** | `<проект>/dsh-media[/<подпапка>]` | Каталог создаётся при первом обращении. В подпапке до 3 простых сегментов, например `shots/2026`. |

В любой из папок лежит одно и то же:

```text
gallery.json      индекс: одна запись на картинку или видео
config.json       несекретные настройки (только в общей студии — см. ниже)
files/<id>.<ext>  сами файлы, имя — сгенерированный id
```

`<DSH_HOME>` — это `$DSH_HOME` или `~/.dsh`; `DSH_IMAGE_STUDIO_HOME` переносит его. Файл настроек **всегда** остаётся в
`<DSH_HOME>/image-studio/config.json`, даже когда медиа указывает в проект: переключатель, направляющий библиотеку,
не должен уезжать вместе с проектом, иначе его нельзя было бы вернуть обратно.

Настроенный проект, которого больше нет (переехал, переименован, удалён), не ломает страницу — студия откатывается к
общей папке, а `library.root` в `/state` говорит, какой корень реально ответил. Переключение источника **не переносит**
уже записанные файлы: у каждого источника своя папка, вторая просто перестаёт показываться.

Если выбранный проект — git-репозиторий и ещё не игнорирует папку медиа, страница предлагает кнопку
**«Добавить dsh-media в .gitignore»**; она вызывает `POST /api/image-studio/gitignore`, который добавляет `dsh-media/`
один раз и никогда не пишет в каталог, не являющийся репозиторием.

Ничего ни из одной из этих папок не отдаётся другой машине: `/api/image-studio/file` отвечает только локальным
запросам, а путь каждый раз собирается из проверенного id — не из промпта и не из удалённого URL. Обе папки можно
спокойно копировать и переносить: `gallery.json` — это индекс рядом с файлами, на которые он указывает.

## Конфигурация

Настройки строки берутся из патча профиля (`~/.dsh/profiles/<профиль>/cordis.patch.yml`) или из строки бандла в
[`cordis.patch.yml`](cordis.patch.yml). Патч заменяет `config` строки целиком, а не сливает ключи, поэтому
переопределение должно перечислять все нужные ключи. Патч профиля также главнее того, что сохранила карточка
настроек.

| Ключ | По умолчанию | Значение |
|---|---|---|
| `falKeyRef` | `FAL_API_KEY` | Ссылка на credential с ключом fal. |
| `defaultModel` | `fal-ai/flux-2/klein/9b` | Модель, выбранная на странице. |
| `customModels` | `[]` | Ваши слаги endpoint'ов fal, добавленные кнопкой **«＋ Своя модель»**. |
| `librarySource` | `studio` | `studio` — общая `<DSH_HOME>/image-studio`; `workspace` — внутри проекта. |
| `libraryWorkspace` | пусто | Абсолютный путь к **существующему** каталогу проекта (нужен при `workspace`). |
| `librarySubdir` | пусто | Относительная подпапка внутри проекта, до 3 простых сегментов (например, `shots/2026`); `..`, абсолютные пути и пустые сегменты игнорируются. |
| `defaultAspect` | `1:1` | Формат по умолчанию. |
| `defaultCount` | `1` | Количество вариантов по умолчанию (1–8). |
| `imageTimeoutMs` | `240000` | Бюджет одной задачи на картинку. |
| `videoTimeoutMs` | `900000` | Бюджет одной задачи на видео; Kling рендерит минутами. |
| `ffmpegPath` | пусто | Исполняемый файл ffmpeg для монтажа; пусто — `ffmpeg` из `PATH`. |
| `updateRepo` | `naletko/dsh-image-studio` | Репозиторий (`owner/name`), у которого спрашивают обновления. |
| `updateCheck` | `true` | Можно ли странице спрашивать GitHub о новой ревизии. |

## HTTP-поверхность

Всё, что делает страница, идёт через собственные локальные роуты плагина — чтобы браузерная половина никогда не
обращалась напрямую ни к провайдеру, ни к ключу, ни к путям на диске.

| Роут | Назначение |
|---|---|
| `GET /state` | Каталог, значения по умолчанию, статус ключа, счётчики, фактический корень библиотеки и блок `library`, статус ffmpeg |
| `GET /workspaces` | Проекты, на которые можно направить библиотеку (`supported: false`, если в сборке нет реестра проектов) |
| `GET /gallery?kind=&q=&favorite=` | Отфильтрованный индекс |
| `GET /file?id=` | Байты медиа для одной записи |
| `POST /credentials` | Сохранить или удалить ключ fal (только запись) |
| `POST /config` | Несекретные значения по умолчанию, список своих моделей и источник медиа |
| `POST /gitignore` | Один раз добавить `dsh-media/` в `.gitignore` выбранного проекта и только для git-репозитория → `{ ok, changed }` |
| `POST /generate`, `POST /video`, `POST /montage` | Поставить задачу в очередь, ответ `202` с задачей |
| `GET /job?id=` | Статус, позиция в очереди, готовые записи |
| `POST /import` | Скачать публичную `http(s)`-ссылку в галерею |
| `GET /update`, `POST /update/apply` | Спросить у GitHub ревизию и отдать её менеджеру плагинов |
| `POST /favorite`, `POST /delete` | Работа с галереей |

Каждый роут отказывает всему, что пришло не с loopback и не с локального origin, тело запроса ограничено 256 КБ, а
медиа читается только из путей, собранных из проверенного id.

## Известные ограничения

- **Только fal.ai.** Провайдер один; другой шлюз — это ещё один модуль рядом с `lib/fal.js`.
- **Пока нет входа с референсом.** Image-to-image и консистентность персонажа на странице не выведены, хотя
  соответствующие endpoint'ы у fal есть.
- **Свои endpoint'ы получают объявленный набор полей.** Свой slug управляется той же формой запроса, что и встроенное
  семейство, поэтому endpoint'у с дополнительными полями придётся отклонить вызов — страница покажет ошибку fal.
- **Импорт принимает только публичные прямые ссылки.** Ссылки на локальную сеть и не-`http(s)` отклоняются намеренно.
  Ссылайтесь прямо на файл: хост сохраняет скачанные байты и определяет тип по content-type ответа, поэтому ссылка на
  HTML-страницу даст бесполезную запись, а не ошибку.
- **Задачи живут в памяти.** Генерация переживает перезагрузку страницы, но не перезапуск харнесса; уже записанные
  файлы остаются в любом случае.
- **Галерея локальная.** Это папка, а не сервис синхронизации.
- **Переключение библиотеки не переносит медиа.** У каждого источника своя папка: записанные файлы остаются там, где
  были, а вторая галерея просто не показывается, пока вы не переключитесь обратно.
- **Монтаж — это склейка, а не монтаж.** Сегменты идут по порядку в одном размере и частоте: пока нет переходов,
  музыки и титров. Нужен `ffmpeg` на машине.
- **Модель не видит видео.** В контент-модели харнесса нет видеоблока, поэтому модель узнаёт путь к файлу. Картинки
  возвращает в переписку тот плагин, который их генерирует, а не эта страница.

## Приватность

**Что уходит с машины.** Только то, что нужно fal для рендера: ваш промпт, настройки генерации для выбранной модели и
— для image-to-video — выбранный кадр, отправленный как data URI. Всё это идёт на `queue.fal.run` по HTTPS, а ключ —
в заголовке `Authorization`. К этому трафику применяются условия и политика приватности fal.

**Что остаётся локально.** Выбранная папка библиотеки — медиа, промпты, индекс — и несекретные настройки, которые
всегда лежат в `<DSH_HOME>/image-studio`. Ключ лежит в хранилище ключей харнесса (или в окружении запуска) и читается
на каждый вызов. Плагин не отправляет телеметрию, не имеет собственного аккаунта и не общается ни с каким другим
сервером. Если библиотека указывает в проект, эти файлы принадлежат проекту: с машины они всё равно никуда не уходят,
но попадут в репозиторий, если не игнорировать `dsh-media/` — для этого на странице и есть кнопка
**«Добавить dsh-media в .gitignore»** и маршрут `POST /api/image-studio/gitignore` за ней.

Другие сетевые обращения, которые он может сделать:

- **проверка обновлений** — читает собственный репозиторий плагина через `raw.githubusercontent.com` и
  `api.github.com` (отключается ключом `updateCheck: false`);
- **импорт**, который вы запросили, — скачивает ровно ту `http(s)`-ссылку, которую вы вставили, на стороне хоста.

Ключ никогда не логируется, не возвращается на страницу и не пишется в файлы конфигурации.
